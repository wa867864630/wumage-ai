# MVP 目标与 AI 设计实施门槛

本轮优化将 AI 管理端蓝图接回 `plan.md` 第 1、2、5、6、9、11 章。用户已确认的对话生成表单、流程和视图方向保持有效，优先用现有课表配置证明自助价值，再逐个扩展实际业务。文档中的阶段和指标是开发/验收标准，不能读作已达标结果。

## 目标与缺口对应

| 原始目标 | 现有基础 | 本轮设计调整 |
| --- | --- | --- |
| 管理员独立完成受控配置 | 列、规则、暂存、试跑、发布、回滚和审计 | 先让 AI 修改这些现有对象，手工操作始终可用 |
| 高频课表请求低成本解决 | 确定性日期规则、技能、数据库模拟课表 | 设计模型只出现在管理链路，不接入学生规则命中链路 |
| 可验证的发布一致性 | 原子包、固定 release_id、数据库真源、Outbox | 提案接受只写草稿；显式发布继续走原接口及回归 |
| 权限与租户隔离 | 可信身份、应用可见角色、查询授权 | 课表 AI 提案不能修改 visible_roles、身份、技能、URL 或数据范围 |
| 配置自助与真实业务有效 | 合成评测和自动检查；真实 UAT/问法仍待提供 | 独立记录真实证据，不用 JSON 合法率冒充请求解决率 |
| 模块化单体与按需扩展 | FastAPI/React、现有版本和审计模块 | 不先创建通用平台表和引擎，不重复发布中心 |

## 两种 AI 使用方式

学生端运行 AI 只在规则未命中、真实评测证明需要且完成审批后，作为受限低风险分类兜底；当前保持关闭。管理端 AI 是本次讨论确认的设计辅助，可在独立配置和预算下使用，但只生成草稿提案，不直接修改已发布配置或业务数据。

两者的启用、速率、预算、失败降级、指标和审计分别管理。设计 AI 失败回到手工配置，学生查询不等待模型。已有“零模型调用”指标继续明确表示学生运行链路；管理端启用后另外显示调用量、费用和失败率，避免对全平台仍作零调用声明。

AI 供应商、数据外发约定与预算尚未选定时，可以开发协议校验和提案预览，使用人工提案或合成样例验证。不能将没有接入的模型标记为可用。

## 课表专用设计协议

新补充的 [course-context.schema.json](../../packages/contracts/application-design/v1/course-context.schema.json) 和 [course-proposal.schema.json](../../packages/contracts/application-design/v1/course-proposal.schema.json) 将范围固定为 `profile=course_query`、`application_id=schedule`。draft 使用现有 DisplayConfig，避免为了采用设计器先迁移数据模型。

| 提案操作 | 可修改内容 | 禁止内容 |
| --- | --- | --- |
| set_column | 已有列的名称、显隐 | 新字段、组件代码、真实字段授权 |
| reorder_columns | 原有列的顺序 | 增删列、重复列、遗漏列 |
| replace_rules | 现有 IntentRule 白名单中的合法规则 | 自定义脚本/正则、绕过否定/多意图/星期歧义护栏 |
| set_application_metadata | 应用名、描述、分类 | visible_roles、租户、身份、接口地址 |

规则列表中的 terms 在前端 Schema 校验后仍需经过现有后端 normalize、safe_terms、发布回归与冲突校验；JSON Schema 无法代替这些 Python 业务规则。未说明是哪一天的别名、同优先级日期冲突等需澄清或显示试跑影响，不静默重新解释。

context.allowed_operations 来自服务端授权配置，提案必须是其子集。列修改只针对 draft 中已存在的 field；重排必须与 draft 的 field 集合完全一致；规则 ID、列 ID 不重复。同一个提案可修改不同列，但不能重复修改同一列；最多一个规则替换和一个重排。元数据、规则、列变化均由服务端生成最终差异，模型 summary 不作为事实依据。

course-context 内嵌现有 `config.schema.json` 的结构定义快照。后续 CI 必须检查两者一致，现有契约升级时显式更新该快照，禁止漂移。课表专用协议现已通过 context/preview/accept 接口接入人工提案；模型生成及通用应用协议仍未接入运行时。

## 首个可演示闭环

1. 管理员加载现有草稿，描述“地点改成上课地点，隐藏教师”。
2. AI 返回两个 set_column 操作，服务端检查基线、权限和最终 DisplayConfig。
3. 页面展示两项变化，使用原课表表格组件预览；管理员拒绝时原草稿不变。
4. 接受后仅暂存新修订，学生查询仍使用旧发布版本。
5. 发布前运行既有固定课表问句回归，管理员明确确认后原子发布。
6. 新学生查询读取新发布 ID，列变化生效，业务课程及日期解释保持不变。
7. 回滚创建新发布记录，草稿和业务数据不被覆盖；模型不可用时同样可手工完成。

不为这条链路增加业务表、流程引擎、动态建表、通用数据视图或 Docker 执行器。提案持久化确有需要时再做最小增量迁移；发布与 Outbox 继续复用现有机制。

## 成功指标与证据

| 指标 | 原目标或新增观察项 | 证据 |
| --- | --- | --- |
| 配置自助 | 3 名目标管理员至少 2 名无研发协助完成配置和发布 | UAT 观察记录，区分手工和 AI 辅助方式 |
| 业务有效 | 至少 100 条冻结真实问法，课表请求解决率 ≥80% | 独立真实脱敏验收集与人工抽检 |
| 学生端成本 | 规则命中不调用 LLM，AI 兜底费用可追踪 | 按管理设计/学生运行分开的调用计量 |
| 性能 | 固定 Mock/本地数据、规定负载下非 AI P95 <300ms | 硬件、数据量、RPS/并发、预热/缓存及错误率完整报告 |
| 发布生效 | 提交后 3 秒内开始的新请求使用新版本 | 发布时间、请求开始时间和 release_id 对照 |
| 权限安全 | 越权和敏感字段外发被拦截 | 租户、角色、字段、scope、提示注入和日志检查 |
| 设计辅助效果 | 观察首次有效提案率、接受率、完成时间、调用数与费用 | 与同任务手工基线比较；尚不预设未经测量的提升幅度 |

真实教务目标需先测量上游后确认；设计生成时间不混入学生查询 P95。227 条合成路由样例、结构校验通过、开发模拟数据和代理环境性能均不能替代真实验收。

原目标的配置自助或低成本请求解决任一项不达标，就暂停平台化扩张，优先定位流程、提示词或运行链路问题。真实资料缺失列为未验收；可以继续本地完善，但不以缺资料为理由把请假或通用平台标记为原 MVP 已完成。
