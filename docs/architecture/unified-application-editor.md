后续架构优化按[扩展架构路线](type-extension-roadmap.md)推进：先统一类型展示描述，再显式能力装配和会话提取。当前共享组件保持复用；不将新版Host视为任意类型执行器，不修改冻结1.0/1.1摘要输入来完成公共重构。

2026-10-23 公共字段导航：FormFieldDesigner提供按当前顺序排列的快速定位、字段/必填计数和单项/全部折叠。折叠只隐藏面板，保留配置与控件；定位展开目标并转移键盘焦点。上述状态只在设计组件本地维护，不进入Schema，不产生保存/模型请求；所有复用类型使用同一交互。新增字段仍按原规则增加，核心字段仍受保护。DOM验证不代表真实滚动或窄屏视觉验收。

2026-10-23 公共字段设计器：FormFieldDesigner已由UnifiedFormEditor抽出，新版登记与请假共用组件、顺序、选项、必填、填写约束和三档屏幕宽度的完整编辑区。接口为config、disabled、protectedFields及onChange(update)，由Host对当前配置副本执行更新并维护未保存/校验状态；组件不调用API、不持有草稿或发布状态。类型以稳定字段key声明核心字段保护，界面说明限制；服务端仍独立校验。扩展类型应复用此组件，不能复制字段设计器或改冻结1.0文件。首版仍限一个分组、30字段及现有七种组件，不表示任意模型结构均可编辑。

2026-10-23 页内显示规范：ApplicationConfigHeading统一栏目标题与说明；统一版编辑器使用application-detail基础输入样式，ApplicationEditorActionBar必须置于application-config-body外，保持与课程一致的留白、通栏边线和底部操作位置。发布记录避免再套独立panel产生双层边框。新增类型应沿用这些结构，专属页内组件不重复包公共操作区。quick与四套DOM通过，真实浏览器/窄屏视觉仍须单独验收。

2026-10-23 公共显示规范：课程及统一版登记/请假共用ApplicationEditorHeader和ApplicationEditorActionBar，统一标题、类型、发布/修改状态、修订与当前栏目、暂存/试跑发布的位置。窄屏操作可换行；业务回调、锁和原请求核对仍由编辑器持有。旧1.0.0冻结编辑器不修改。

新增类型的界面约定：按精确版本注册编辑器，复用ApplicationSettingsFields、ApplicationConfigTabs、ApplicationEditorHeader、ApplicationEditorActionBar和发布变更核对组件。基础信息、访问范围、状态词、公共按钮名称与布局不得另造一套；专属配置放在能力对应的页签内。组件只展示和发出事件，不自行保存、授权或声明发布成功。新增能力必须配套服务端校验/执行和同任务回归；复用公共界面不代表自动获得运行能力。

## 1. 当前问题与已实施范围

课程 ConfigAdmin 有独立页签、基础信息和发布交互；登记 FormEditor 自带另一套；请假 ApprovalEditor 复用登记，但流程内容为写死的图和不可编辑审批人来源。服务端审批 Schema 也限制为一个审批节点，AI生成协议要求保持默认 workflow，所以当前并无可用的流程设计能力。

本段已提取 ApplicationSettingsFields（名称/分类/说明/访问角色）和 ApplicationConfigTabs（统一导航、选中状态、键盘及焦点），由课程编辑器实际使用。登记/请假旧编辑器尚未迁移；不能把这两个组件的存在称为三类界面已统一。旧表单/审批实现字节和类型摘要保持不变。

第二段历史进展：后端引入不可重复覆盖的编译期ExactTypeRegistry，前端编辑器改为按类型/版本匹配，隔离测试验证合成版本并存。该段当时只安装1.0.0；此后本轮已实际接入1.1运行与创建，见本文顶部。原证据 `.local/checks/editor-version-registry-20261022.json`。

## 2. 界面固定结构

工作台左侧保持应用列表；右侧应用标题、发布/草稿/未保存状态、应用编号和公共操作位置固定。默认进入基础信息。公共页签使用稳定标识，类型不自行重写公共名称、排序或按钮行为。

| 页签标识 | 统一名称 | 内容及开放条件 |
| --- | --- | --- |
| basic | 基础信息 | 名称、分类、说明、可使用角色；所有类型共用 |
| design | 页面与表单 | 课程展示、表单字段等类型设计槽位；只有内容区别 |
| workflow | 流程设计 | 仅注册了可编辑且可执行流程能力的类型显示 |
| questions | 对话入口 | 只对已支持实例问法维护的类型开放，不给表单伪造课程日期规则 |
| preview | 预览与校验 | 公共布局，类型提供试填/试跑及校验结果 |
| records | 业务记录 | 支持记录的类型开放，复用分页/空/失败/详情规范 |
| history | 发布记录 | 同一发布/恢复交互，按具体类型验证 |

暂存、预览、发布、使用应用、重新加载的位置和状态规则统一。未保存时先暂存再发布；未知结果锁定原请求核对；切换应用保留未保存保护。业务数据操作不放进设计暂存，也不把发布应用配置当作部署平台。

已有 course page 等历史导航标识应通过显式映射兼容，不直接改旧链接。能力缺失时不显示空页签，不用CSS隐藏另一套完整编辑器，也不以模拟点击旧DOM连接公共组件。

## 3. 组件与状态职责

| 公共部件 | 平台职责 | 类型提供的内容 |
| --- | --- | --- |
| ApplicationSettingsFields（已实施） | 基础字段和访问角色的受控编辑 | application值及变更回调 |
| ApplicationConfigTabs（已实施） | 导航语义、键盘、选中与面板关联 | 能力允许的页签清单 |
| ApplicationEditorHost（待实施） | 应用上下文、统一状态和页面装配 | 精确版本适配器 |
| EditorActionBar（待实施） | 暂存/预览/发布/使用/重载及禁用规则 | 命令实现，不接收任意URL或脚本 |
| PublishHistoryPanel（待实施） | 发布列表、差异与恢复确认 | 类型化内容比较/校验 |
| FormFieldDesigner（待抽取） | 选择组件、顺序、选项、校验、12等份宽度 | 受保护字段及允许组件 |
| WorkflowDesigner（待实施） | 文字/AI提案、节点列表和只读流程图 | 执行器支持的节点、规则和人员解析能力 |

平台会话只保存一种草稿状态：saved、editing、saving、unknown、conflict及对应错误/发布状态。应用身份、修订、幂等键、锁、离开保护、审计继续复用既有服务，不能由每个类型再写一套。基础字段组件仅发出新值，不保存、不自行授权。类型扩展只声明能力、设计内容和业务约束，不再提供整套工作台。

## 4. 已有类型的兼容前置

登记1.0.0的摘要包含 FormEditor/FormRuntime，审批1.0.0包含 ApprovalEditor/ApprovalRuntime并依赖登记摘要。直接修改这些文件会使已创建应用/发布绑定校验失败。禁止通过重算旧摘要、改数据库、跳过校验或把旧文件留作摘要摆设解决。

迁移先建立按(type_id,type_version,type_digest)精确解析的前后端注册机制，旧1.0.0实际实现与旧路径继续保留。新类型版本使用公共编辑器，形成独立产物摘要。公共组件由平台源码/构建版本追踪，类型声明其兼容的编辑协议；不能因此取消类型运行实现的固定绑定。

新应用才默认使用验证后的新版本。现有实例不后台自动升级；只有确定性草稿转换、差异、试运行和明确确认齐备后才开放升级。旧发布和在途申请继续原版本，回滚配置不改变类型版本和原审批人。前置未完成时，只可迁移不改变旧摘要的课程公共部分。

## 5. 流程配置范围

第一段默认以单级可执行能力为边界，先完成节点名称等现有Schema允许字段的手动编辑、AI提案核对、保存、校验、预览和发布，移除只展示硬编码流程的假设计体验。只有执行器实际支持的字段才开放编辑；当前Schema未支持的说明/策略不能只在前端加字段。

| 能力 | 当前实际情况 | 后续要求 |
| --- | --- | --- |
| 流程名、审批节点名 | Schema已有，界面未开放 | 新编辑器通过正式配置草稿保存 |
| 选择其他审批人 | 只有已认证发布管理员 | 需要可信人员目录和服务端解析，不接受自由输入人员ID |
| 多级串行 | 单节点执行器不支持 | 新流程协议、任务/状态迁移、完整事务和审计，再开放节点增加 |
| 条件分支 | 不支持 | 字段类型化条件、覆盖/死路/循环校验、执行快照和分支回放 |
| 超时、抄送、通知 | 不支持 | 配套任务/Outbox及明确失败恢复后才开放 |

“请假3天以上走第二级”等要求不能通过改图完成。AI输出受能力Schema限制，无法执行时应解释并澄清，不生成看似可发布的流程。发布前显示节点/审批人来源/规则及实际变化；新流程只影响新申请，不重新解释在途申请。

## 6. 实施顺序与验收

1. 已实施：提取基础信息与导航，课程编辑器采用公共组件，保留现有字段/链接/写入语义；本段报告见 `.local/checks/editor-foundation-20261022.json`，真实结果以报告为准。
2. 当前段：精确版本解析注册与旧实现兼容测试；不混入流程能力扩展，不修改用户实例或发布。解析基础已落地，后续还须补新版本运行适配器、模板/创建版本选择及新旧API绑定，才可迁移编辑器。
3. 第三段：新版本登记/请假迁入统一Host、基础/操作区/预览/历史，字段设计共用。此时以三个类型同任务对照验收，非仅组件单测。
4. 第四段：开放单级流程名称/节点配置及AI提案闭环；若需求转向多级或分支，先补执行协议与在途版本规则，再开发设计器。

每段完成源码基线、兼容检查、全量相关回归和恢复验证；真实浏览器检查同一字段是否同样式/布局/键盘行为、窄屏操作、未保存切换、结果未知核对。此改造不删除已有业务数据，不自动发布应用；生产构建和Git提交限制仍单列。
