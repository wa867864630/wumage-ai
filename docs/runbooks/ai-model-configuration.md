# 管理端 AI 模型配置与课表生成

当前支持单个已保存的 Chat Completions 兼容模型，用于课表设计、问法批量生成及本地演示租户的低匹配查询兜底。规则命中不调用模型；通用表单、审批和数据视图生成尚未接入。

## 问法库：生成、学习与审核发布

入口：“微服务广场 → 应用管理 → 应用工作台”，自动加载当前应用后，切换“问法与规则 → 问法库”。

1. 问法库自动加载，默认显示待审核项，可手动刷新，按状态、来源、文字筛选及观察次数排序；列表每页20条。
2. 点击“新增问法”，在侧边抽屉填写问法及日期含义并保存；点击列表“查看/编辑”可修改或审核。也可选择1～20条，点击“AI 批量生成待审核问法”。批量生成使用当前应用说明和明确支持的课表能力，不读取学生记录，重复问法跳过，不覆盖已有审核结论。生成使用现有模型开关、次数额度和并发限制，记录模型/提示词版本/用量审计；本轮以模拟模型验证协议，真实供应商批量生成仍需在页面验收。
3. 学生问句未被规则匹配、AI解释通过校验且教务查询成功后，符合学习条件的问法自动进入待审核库。重复出现合并观察次数，记录AI日期解释的分布。这里的次数不是独立用户数，也不证明解释正确；多种解释冲突时不能审核，需先修改。采集失败不影响查询结果，运行指标记录失败。
4. 查看来源（管理员新增/AI批量生成/真实查询学习）、状态、观察次数及当前草稿/发布是否含该规则。点击“审核通过并加入草稿”，系统执行日期冲突与固定回归检查、原子写入规则草稿及审核审计。然后使用原有“校验并试跑草稿 → 发布应用”。只有发布后，下次相同规范问法才直接走规则。数据来源只表示创建来源，修改后仍需重新审核。
5. 修改会回到待审核、移除该问法的草稿旧规则并清空旧观察计数；拒绝、停用、删除同样移除草稿专属规则。已发布内容保持到下一次发布，不会因库状态变化自动修改。删除采用保留记录的方式防止自动重新推荐；拒绝/停用项也不会被学习自动恢复。回滚可能恢复旧规则，因此“审核状态”和“当前发布含此规则”独立展示。

首版只编译为现有exact规则，支持今天、明天、后天、本周、下周；每次查询重新解释相对日期，不缓存课程结果。暂不自动学习固定年月日、具体星期、任意日期参数模板、其他业务或否定/多操作表达。明显账号/凭证/长数字等信息会被拦截，基础筛查不等于完整个人信息识别，管理员仍应查看内容。每组织最多500条记录（含删除记录），每条启用问法占用一条现有规则，草稿总上限50条；满额会提示，不静默扩容。未实现语义向量检索、自动启用、批量审核、独立用户计数或学生纠错入口。

新增迁移`0004_question_library`仅创建`question_candidate`表，不改已有业务表、草稿或发布快照。本机已执行并核对配置摘要保持一致；其他环境按正常Alembic升级流程执行至head。UI及审核接口具有问法修订和草稿修订检查，出现冲突或网络结果不确定时刷新工作台与问法库核对状态。

## 配置入口

在本机通过 `http://127.0.0.1:5173` 使用管理令牌登录，进入“微服务广场 → 应用管理 → AI 模型配置”，点击“加载模型配置”。当前配置维护及调用仅开放给 demo 模式下本地 local-demo/local-admin，不向其他租户、学生或远程来源暴露本机模型密钥。

本次按用户提供的测试参数保存并启用：

| 配置 | 当前值 |
| --- | --- |
| API 基础地址 | `https://api.deepseek.com/v1` |
| 模型名称 | `deepseek-chat`，按用户指定保留，不自动替换 |
| 长度参数 | `max_tokens` |
| JSON 模式 | 启用 |
| 超时 | 60 秒 |
| 最大输出 | 4096 tokens |
| 单操作者小时调用上限 | 20 次，测试与生成共用限制 |

API Key 不写入本文，不返回配置读取接口或 HTML。需要替换时在密码框输入；留空保留旧密钥。更换 API 地址会清除旧密钥，启用新地址必须重新输入，避免无意把原供应商凭证发给另一个地址。清除密钥时同时关闭启用开关。

保存后立即生效，无需重启 API。并发保存按 revision 检查，冲突时重新加载。测试按钮使用已保存配置，真实调用模型并产生用量，返回固定 JSON 检查结果，不发送设计或学生数据。远程地址必须 HTTPS；HTTP 仅允许明确本机地址；基础地址不填写 `/chat/completions`，请求端不跟随重定向。

## 生成提案

2026-10-20 增量：启用的同一模型也用于本地演示租户的低匹配课表查询兜底。规则完整命中（内置语法或已发布规则）直接查询，AI 用时为0；未命中且通过否定、多日期、星期歧义、规则冲突等检查，才发送问句和校园当前日期给模型，不发送课程记录或学生身份。模型返回规范问句与置信度，置信度至少0.9且规范问句通过规则解析才查询；原问句的明确日期不可被模型改写。这里的规则匹配为命中/未命中，不伪造相似度百分比。AI 失败、限流或不确定时保留澄清，最多等待10秒，不自动重试。关闭模型停止兜底；其他租户和OIDC不使用本地演示凭据。

查询结果显示浏览器测得的总用时（含网络）和服务端测得的AI调用用时。`ai_used=false` 时 `ai_duration_ms=0`；已调用但失败也计AI时间。预算或并发限制在发出请求前拒绝，不计AI时间。查询调用单独记入`query_llm_*`，设计调用仍为`design_llm_*`，共享现有每操作者小时额度与全局并发限制。进程指标`llm_calls`现在反映真实查询调用数，不能继续固定解读为0。现有默认模型开关同时控制设计及演示查询，不支持独立预算和多租户凭据。

进入“应用工作台”，加载并暂存当前手工编辑。在“课表配置提案 · AI 辅助设计”填写：

> 把地点改成上课地点，隐藏教师，其他设置不变。

点击“使用 AI 生成提案”。后台构造当前草稿、白名单操作、输出 Schema 和基线绑定；模型只收到设计元数据及这段需求，不收到学生课程结果或密钥。每次生成以服务器已保存草稿为基线，首版不保存连续聊天；连续调整应先接受已有提案，或重新完整描述希望的修改。

响应经严格 JSON/类型校验、绑定检查和课表回归后展示差异。若缺少关键业务信息，则显示澄清问题；补充需求后重新生成。生成期间草稿或模型配置变化，结果被拒绝，不能直接接受过期候选。模型结果不合法时不自动修复或重试，也不改变原草稿。

修改需求会使旧预览失效，但保留编辑器中的上一份 JSON；新提案成功返回才替换它，失败时可继续编辑或重新校验旧提案。下方 JSON 不会随需求文字自动改变，接受前务必核对实际差异。纯空白需求在服务端拒绝，不消耗模型调用额度。

确认差异后点击“接受提案并暂存”，再走原有试跑和显式发布流程。生成、暂存、发布是三件独立操作；学生始终使用已发布版本。生成失败、模型关闭或供应商不可用时仍可使用手工配置和人工 JSON 提案。

## 密钥与持久化

配置保存在根目录 `config.ai-design.secret`，密钥用 Fernet 加密，解密材料在 `config.ai-key.secret`。两者均由现有 `*.secret` 忽略规则排除，且不属于发布包文件白名单；不能复制到文档、版本库、前端包或普通日志。

解密材料丢失时在配置页重新输入 API Key；不要删除现有业务库或 config.local.toml。文件采用同目录临时写入和原子替换，设置仅所有者读写的文件模式；Windows 实际访问控制仍由目录 ACL 决定。两份文件同处本机，这种加密不替代操作系统账户保护或生产 Secret Manager；当前功能明确限定本地开发管理。

模型配置不属于应用发布内容，不因课表回滚而恢复旧凭证。配置修改以本地 revision 标识，不具备跨进程数据库事务；当前单进程使用，不作为多实例平台凭据管理方案。

## 用量、审计及限制

单次调用受超时、最大输出 token、1 MiB 响应及 128 KiB 提案限制。每操作者同一时刻一项调用，全进程最多两项；发出尝试即占用调用额度，无自动重试。小时调用额度与运行指标是进程内数据，重启重置，不是持久金额预算，也不替代供应商账单或账户限额。

管理端使用 `design_llm_*` 指标单独统计调用和供应商返回的 tokens，学生运行链路的 `llm_calls=0` 只描述学生查询。生成成功后写 `design_ai_generate` 审计，记录模型、配置 revision、提示词版本、用量、请求 ID 和提案摘要，不存密钥、完整上下文、原始模型回复或思考过程。调用失败计数留在运行指标；尚无完整持久化生成任务和失败用量台账。

首版采用非流式单次生成，没有工具执行、模型自动发布、服务端生成任务取消或自动修正。关闭页面/请求超时不能保证供应商停止计费；先核对调用结果再决定是否手动重试。不同兼容接口在参数和模型行为上仍可能不同，需对每个实际模型做连接及生成验收，不承诺原生 Anthropic/Gemini 等协议兼容。

实现参考 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 和 [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。JSON 模式约束输出形态，业务类型、引用、权限和原日期规则仍由本系统再次校验。
