## 课表配置提案验收

当前已实现 JSON 提案的校验、差异预览和接受草稿，并已增加 AI 生成入口，无新增数据库迁移。重启后端或确认自动重载已完成，刷新前端，使用管理员进入“微服务广场 → 应用管理 → 应用工作台”。

1. 点击“加载 / 重新加载”，先暂存已有手工修改。
2. 在“课表配置提案 · AI 辅助设计”点击“载入当前基线与示例提案”。示例绑定服务端最新草稿修订和摘要，默认只调整一个已有列的名称；也可使用自然语言生成提案。
3. 点击“校验并预览提案”，查看服务端核对的变更及合成课程表；此时数据库草稿和学生发布版本均不改变。
4. 点击“接受提案并暂存”并确认。草稿修订增加，学生仍使用原发布版本。随后走原“校验并试跑草稿 → 发布应用”流程；本轮自动测试不发布用户配置。
5. 编辑提案中的 visible_roles、未知列、重复操作、遗漏列重排或错误基线应被拒绝；字段错误显示路径和请求编号。内置日期规则被重新解释时，回归阻止接受。
6. 接受结果不确定时保留相同请求号重试，不重复增加修订；页面同时阻止新的编辑/保存/发布/回滚。重新加载需确认并核对草稿与审计；即使发生后续编辑，旧请求重放也不恢复旧草稿。

接口为 `GET /api/v1/admin/course-display/designer/context`、`POST .../designer/preview`、`POST .../designer/accept`。POST 在鉴权后进行 128 KiB 字节限制与严格 JSON 解析，拒绝重复键和非有限常量；UI 原样发送 JSON 以保留这些检查。服务端只接受课表列、顺序、合法规则及元数据操作，不提供角色修改或发布动作。

接受使用现有 config_state 行锁和 config_audit 实现同事务草稿/审计提交；审计动作 `accept_course_proposal` 的 after_json 包含 content、request_hash 和原接受结果。按租户、操作者、配置 key 和接受请求号生成持久化命令标识，重复请求核对请求摘要。接受记录承担幂等职责，在明确迁移幂等存储前不得清理这类审计记录；此阶段没有独立的模型生成或提案管理表。

本轮 90 项后端测试（含 openGauss 隔离集成、重复/并发接受、审计失败回滚、角色/租户隔离及晚到重试）全部通过，无跳过。前端类型、提案面板 SSR、HTTP 错误/原始 JSON、契约检查和 227 条合成问句通过；运行中课表 23 项闭环通过，新增 context/preview 实际返回 200 且有可接受变化。未在用户草稿上执行接受或发布；浏览器点击、确认及断网恢复交互仍需手工验收，本轮未重新生产构建。

## 最新课表规则补充：具体星期与日期同义词

规则版本为 `course-query-v1.2`，不调用 AI。登录后查询“本周五有什么课”“下周三课表”“下星期一课表”“下礼拜日有课吗”，结果应为对应单日；今日/明日/后日与今天/明天/后天一致。周一开始、周日结束，以 Asia/Shanghai 为准；“本周五”即使已经过去，也不自动查下周。

“周五课表”“星期一课表”应要求明确本周或下周。“下下周三”、多日期、否定或混合指令不执行；管理员不能使用别名将这些表达强制映射成某一天。管理员新增的明确星期规则若改变了日期，应在预览/发布回归中被拦截。

## 2. 学生查询

1. “明天课表”“明天有什么课”“【明天有什么课】”应得到相同日期；本周为周一至周日，下周正确跨周。
2. “2026-10-19课表”应返回模拟课程；查询周末应成功显示没有课程。
3. “查课表”明确提示默认今天；“下周三课表”查询下周三单日，“周三课表”“今天和明天课表”要求明确日期，不猜测执行。
4. “我要请假”“今天课表，帮我请假”不办理其他业务；否定句不执行。
5. 日期倒置、超过 31 天或无效日期显示错误。Network 中请求包含 `X-Trace-ID` 和 `Server-Timing`，可区分应用、配置和上游耗时。
6. 页面未知组件格式显示降级文字，不执行后端下发代码。

## 3. 配置自助闭环

1. 打开配置管理，输入本地管理 token 并加载；错误 token 不能读取或修改草稿。
2. 修改展示名称、顺序、显隐；新增精确规则“明日课程”，日期选“明天”。或新增关键词规则，词条分别为“明日”“课程”，日期选“明天”。
3. 试跑草稿：输入“明日课程”，查看解析日期、同一组件渲染的模拟课表、发布影响与合成问句回归。
4. 保存草稿后，学生查询“明日课程”仍不命中新规则；只有管理员预览可看到草稿效果。
5. 点击发布。学生重新查询后，新规则和新字段展示同时生效，并携带同一发布 ID。
6. 添加同优先级、相同问法但不同日期规则，预览和运行时应要求澄清；把“明天课表”强行映射今天会触发回归，不能发布。
7. 发布两次后回滚到第一版：新建回滚发布记录，注明“恢复内容自”源 ID，字段和规则一起恢复，历史与草稿不删除。
8. 审计列表展示操作者、时间、动作、请求编号及变更前后内容。重启后草稿、发布历史、当前配置和审计仍在。
9. 两页同时加载后分别保存，只能第一份成功，第二份提示冲突。发布返回不确定时可用原请求号重试；重新加载后先核对版本再继续操作。

## 4. 故障与监控

- 管理区“刷新运行指标”显示单进程计数、零模型调用和 Outbox 状态；指标重启后重置，数据库审计与事件不重置。
- Worker 消费事件只写版本化缓存，不更新发布指针；乱序或重放旧事件不让配置倒退。失败退避重试，最多 8 次，管理员可重新投递；进程退出后过期租约可恢复。
- 可选 Redis：先安装新依赖，启动独立 Redis，在配置文件增加 `[redis]` 和 `url = "redis://127.0.0.1:6379/0"`，重启 API/Worker。Redis 故障自动回源数据库，不把缓存当真源；不缓存学生课表。
- `docker compose up -d redis` 只用于已有 Docker 的环境。已有远程 openGauss 不需要启动 Compose 的 PostgreSQL 服务。
- 数据库不可用时，查询与管理返回明确 503；不会显示“无课程”或静默启用另一份配置。
- `/api/v1/admin/metrics` 提供受管理权限保护的 Prometheus 指标。`infra/monitoring` 包含抓取、告警、Grafana 导入示例；真实令牌通过本机外部文件注入，不能提交仓库。Collector/Prometheus/Grafana 未在当前机器部署。
- OpenTelemetry 可选：安装 `requirements-observability.txt`，设置 `[telemetry] enabled = true` 与 OTLP HTTP `endpoint`。只发出匿名请求/配置/规则/上游阶段 span，不记录问句、身份、令牌或数据；当前未接入 Collector。

## 5. 校园真实接入条件

这些部分具备适配代码，但缺少外部资料，不能标记真实验收通过：

- **身份**：需要 issuer、audience、HTTPS JWKS URL、角色/租户/教务账号 claim 映射和测试账号。配置 `[auth] mode="oidc"` 后，服务端验证 RS256 签名、有效期、issuer、audience 和必要声明，失败不回退模拟身份。角色 `student`/`teacher` 可查自己的关联账号，`config_admin` 可管理本租户配置；`platform_ops` 不隐式获得学生数据或配置写权限。当前前端支持输入访问令牌，不含自动跳转 SSO/PKCE 登录流程。
- 新租户需运维显式初始化配置：在 `apps/api` 目录执行 `../../.venv/Scripts/python.exe -m app.manage seed-tenant 真实租户ID`。不会覆盖已有配置；请求不能任意创建租户。学生 ID 与租户来自可信身份，不接受客户端指定查询对象。
- **教务**：需要接口文档、服务账号、测试数据、校历/周次和调课规则。配置 `[sis] mode="http"`。当前提供的是标准适配契约，不宣称已适配某所学校的原有接口：服务端 GET 固定 HTTPS URL，传 student_id、tenant_id、start_date、end_date 和服务端 Bearer token。响应必须是 `{"student_id":"...","tenant_id":"...","courses":[...]}`，course 字段见生成的 OpenAPI。实际接口不同则在适配层映射。
- 教务接口超时、身份不匹配、日期越界、课程字段不合法时返回错误；404 表示账号未关联；明确的空数组才是没有课程。失败熔断、并发上限和总超时已实现，不盲目重试。
- 100 条以上真实脱敏问句、独立验收集、三名目标管理员 UAT 及试点峰值负载需要业务方提供。合成开发样例不能冒充真实证据。
- AI 分类是原计划的可选项，需真实规则评测未达标且完成模型审批才接入；当前明确关闭，所有请求模型调用和成本为零，不把缺少供应商的接口当成可用 AI。
