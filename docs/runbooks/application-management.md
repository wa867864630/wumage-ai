校园助手不再固定锁定原课表。进入校园助手或开始新对话后显示“自动匹配应用”，可直接输入：

- “本科课表查询明天课表”：先识别实例，再将业务问句交给该应用。

- “切换应用”或“取消锁定”：回到应用选择；也可直接说“打开另一个应用名”。

## 模板新建到实际使用（最新，2026-10-20）

开发地址：`http://127.0.0.1:5173/#workbench`。管理员登录后应看到“管理你的应用”和蓝色“＋ 新建应用”按钮。左侧读取真实应用列表，默认选第一项；右侧显示当前应用及类型版本。

1. 点击“＋ 新建应用”，选择“标准课程查询”或“简洁课程查询”模板，填写应用名称，点击“创建并开始配置”。新实例默认未发布，只在管理列表出现。
2. 在右侧基础信息中修改名称、描述、分类和访问角色，或到页面配置调整课程列名、顺序和显隐，然后“暂存更改”。简洁模板默认隐藏教师。
3. 可切换“问法与规则”，维护本应用的问法、审核候选，或显式调用模型批量生成待审核问法。审核只改本应用草稿，仍需发布。新实例的 AI 页面设计提案暂未开放，原课表 AI 设计继续可用。
4. 点击“试跑发布”→“校验并试跑草稿”→核对结果→“确认发布”。发布后显示“已发布”和“使用应用 ↗”，左侧状态同步更新。
5. 点击“使用应用 ↗”，直接进入当前应用的对话界面；也可回到微服务广场搜索新应用名称后“使用微服务 ↗”。左侧已开通微服务也会显示新应用。查询固定使用所选实例的发布配置，日期查询同样适用。
6. 再回工作台选择其他应用，可以核对各自独立的名称、字段、问法、发布记录和审计。切换有未保存修改时提示放弃；正在写入或结果待确认时禁止切换。

创建、发布遇到响应丢失时保留原请求号重试，不重复创建/发布。已明确拒绝的创建请求允许修改后重试。切换组件按实例卸载并取消旧读取，避免晚到响应覆盖新应用。页面首次加载及打开创建面板不调用模型。

目前两个模板都属于课程查询类型，共用平台当前教务读取能力，仍只查询当前身份本人的课程；模板复制不创建数据源或新业务数据。表单、审批、库存等不能用课程模板冒充实现。对话自动发现应用、对话引导管理、应用生命周期及类型升级仍为后续工作。

新增管理接口 `/api/v1/admin/applications/{UUID}/configuration` 及其 draft/current/preview/publish/rollback/releases/audit/monitoring，问法接口 `/questions`；运行接口 POST `/api/v1/applications/{UUID}/query` 和 GET `/schedule`。新应用未发布返回404，无使用角色返回403；目录仅含获授权发布快照，草稿名称及未发布内容不进入用户目录。旧 schedule 路径保持不变。

迁移 `0006_application_runtime` 只增加可空 runtime_binding 字段，旧发布不重写；之后的新发布固定应用ID、类型/摘要、数据绑定与课程能力契约，读取及回滚复核。开发库已迁移，五张原表旧字段记录数/摘要保持一致。前端状态回归使用模拟 React DOM，后端 HTTP 闭环使用独立数据库 Schema；没有向用户应用库写验收应用或调用真实模型。

5173 的页面、当前新模块及 API 代理已验证200。当前执行环境正常构建仍报 spawn EPERM；改用 native 配置加载同样失败，未更新旧 dist 产物。请在上述开发地址验收，部署地址需在可正常构建的环境执行 pnpm build 后更新。DOM 回归不能替代真实浏览器视觉及移动端验收。

## 后续方案：Docker 离线部署（暂缓实施）

用户已确认先记录方案，待 MVP 核心功能完善后再做。以下内容是后续设计，不是已实现功能；本阶段不继续开发安装、上传、加载镜像、远程更新或提权执行器。

采用“环境安装包库 + 离线镜像包 + Compose 模板”。检测系统发行版、版本、CPU 架构、内核及 Docker/Compose 状态；已有兼容 Docker 优先复用，无 Docker 时按已验证的兼容矩阵匹配安装包和完整依赖。首期限定 Ubuntu 22.04/24.04 + amd64，其他平台逐一验收，不能把某个包用于所有 Linux。联网可从受控包库获取，离线则预先收齐所有文件；离线部署不得临时联网补依赖。

材料分为三类：

| 材料 | 必要内容 |
| --- | --- |
| 环境包 | 系统/版本/架构、Docker Engine/CLI/containerd/Compose 插件及完整依赖、版本和校验摘要 |
| 镜像包 | 含 Python 与应用依赖的后端镜像、含已构建前端的 Nginx 镜像；记录平台、不可变镜像标识与归档摘要 |
| 部署模板 | 固定 Compose 模板、配置模板、端口与卷、增量迁移、健康检查及应用版本恢复步骤 |

API 和 Worker 共用后端镜像、分别启动；构建机完成前后端构建，目标机只运行容器。继续连接现有 openGauss；数据库容器是可选项，不自动替换已有库。密码、运行配置、证书和业务数据放在镜像外，按权限挂载或注入；更新只替换应用镜像，保留配置和数据卷。

预期流程：只读检测 → 匹配并校验环境包/镜像包 → 展示最终计划并确认必要提权 → 安装缺失运行环境 → 上传校验 → `docker load` → 准备配置/数据卷 → 确认备份并迁移 → Compose 启动 → 健康检查 → 记录结果，失败恢复旧应用版本。Docker 安装冲突时停止，不自动卸载已有运行环境；不接管未核对的端口或站点，不使用任意输入脚本，不承诺数据库自动逆向回滚。

容器仍依赖宿主机内核和 CPU 架构，需要分别准备 amd64/arm64 等镜像，不能宣称完全解决兼容性。Docker 安装和镜像生命周期参考 [官方 Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)及 [镜像归档说明](https://docs.docker.com/reference/cli/docker/image/save/)。后续实施顺序为 Dockerfile/生产 Compose → 离线包清单及校验 → 环境匹配与计划 → 执行确认 → 上传/安装/启动/恢复与真实验收。

## 设计暂存和发布验收

1. 使用现有管理令牌登录，进入应用工作台；课表应用自动选中并加载基础信息，右上角可重新加载。
2. 修改应用名称或描述，点击底部“暂存更改”；刷新页面、重新登录后，修改仍应存在。
3. 暂存后学生目录及查询继续使用旧发布版本，不会立即采用草稿。
4. 点击底部“试跑发布”，在面板中“校验并试跑草稿”，核对变更与回归结果，再“确认发布”。刷新/重新进入广场后，应显示新名称、描述和分类。
5. 如更改可见角色，发布后未授权角色的目录不显示该应用，日期和自然语言接口都返回 403，不只是前端隐藏。
6. 回滚旧版本时产生新的发布记录并立即生效。原发布记录不覆盖，暂存草稿也不被回滚静默改写。
7. 未暂存时离开编辑器、退出或关闭页面，应收到离开提示。暂存采用修订号防止覆盖他人修改。

只编辑已注册的课表能力；暂不支持任意创建技能、上传可执行代码、通用拖拽或工作流。应用信息随现有配置发布包保存，无新增数据库表/迁移；旧记录读取时补默认值，不批量重写历史。

## 显式开启本地 SSH 检查

仅在你自己的开发机安装可选依赖：

```bash
./.venv/Scripts/python.exe -m pip install -r apps/api/requirements-deployment.txt
```

在已被忽略的 `config.local.toml` 增加配置节（不要复制覆盖已有数据库或令牌）：

```toml
[deployment]
enabled = true
operator_subjects = ["local-admin"]
allowed_hosts = ["192.0.2.10"] # 示例地址，必须替换为实际授权的服务器 IP

# 核实后建议配置固定指纹；下面只是格式说明，不是真实指纹：
# [deployment.host_fingerprints]
# "实际IP:22" = "SHA256:从服务器控制台独立核实的指纹"
```

重启本地 API。应用管理员身份并不会自动授权服务器操作；`operator_subjects` 是独立许可名单。入口还要求 demo 开发模式、请求来源和 Host 均为本机，以及允许的本地页面 Origin。线上保持 `enabled = false`，不要把本地部署助手通过隧道公开。

### 指纹与只读检查

1. 点击“检查本地部署权限”，确认独立授权和依赖。
2. 填入授权的明确 IP、SSH 端口和用户名；首次**留空密码与指纹**，点击“仅获取主机指纹”。该步骤只建立 SSH 握手，不发送账号密码。
3. 通过服务器控制台等独立渠道核实 SHA256 指纹，不要仅因页面显示就信任。手动填入核实后的指纹，建议同时将它写入本地 `host_fingerprints` 配置并重启。
4. 填入本次密码，执行只读检查。服务端每次都会先比较主机指纹，再发送密码；配置中的固定指纹优先，页面无法覆盖它。
5. 检查只读取 Ubuntu 版本，并检测 python3、systemctl、nginx、sudo 命令是否存在。不执行安装、不提权、不上传、不改文件、不启动/重启服务、不连业务数据库。只支持 Ubuntu 22.04/24.04 模板，其他系统标记不支持。

密码仅经本机请求使用，页面请求完成后清空，服务端不保存到文件、数据库、部署记录或日志。错误不会返回原始 SSH 输出；输出大小、时间和并发有限制。SSH 认证失败不会被误当成校园登录过期。首期不支持域名、密钥认证或多因素 SSH；有需要再扩展。

当前环境尚未安装可选 Paramiko 依赖，也没有进行真实 SSH 联调。测试使用假的 SSH 传输对象，证明顺序、固定命令、边界和资源释放，不证明某台真实服务器已可部署。实现依据 [Paramiko Transport 官方接口](https://docs.paramiko.org/en/stable/api/transport.html) 与 [Channel 官方接口](https://docs.paramiko.org/en/stable/api/channel.html)。

## 安装与更新计划审阅

先按下一节生成本地发布包，再填写连接信息、版本号（小写字母/数字/连字符，最多 64 字符）及脚本输出的 64 位小写 SHA256 摘要，点击“校验产物、重新检查并生成计划”。每次请求后密码会清空，生成计划前需重新输入。`POST /api/v1/admin/deployment/plan` 先验证本地发布包，缺失、损坏或版本号不符时返回 409，不建立 SSH 连接。随后沿用本地来源、独立授权和目标白名单，重新进行 SSH 指纹验证及只读检查，不接受浏览器提交的检查结果；仅 Ubuntu 22.04/24.04 且具有 systemd 时生成计划。

计划绑定实际核验的指纹、IP、端口、用户名、操作、版本及产物摘要。固定版本目录为 `/opt/campus-ai/releases/<版本号>`，不接受自定义路径或命令。页面展示备份、目录检查、缺失依赖、产物校验、运行配置、服务、迁移、健康检查和恢复步骤；提权步骤单独标注。任一表单输入变更后清除旧计划，避免误认其仍对应当前输入。

计划摘要用于比较内容，不是执行授权或持久化部署记录。本地产物已验证不代表可以部署；实际产物尚未上传服务器。生成计划增加下述固定只读探针，不安装、不写服务器文件。执行接口及确认流程仍待实现；执行前必须重新检查并确认最终计划，不能直接执行当前审阅结果。

### 服务器执行前检查

生成计划时，在同一次已核验指纹的 SSH 连接中运行固定 Python 探针。唯一参数是经过严格校验的版本号，服务端不接受任意脚本或命令。普通“只读检查”入口继续保持原有基础检查。

探针读取目录元数据、`current` 指向、磁盘可用量、Python 版本与 venv/ensurepip 模块、`/proc/net/tcp*` 监听状态，并执行固定的 `systemctl show` 查询 `campus-api.service`、`campus-worker.service`、`nginx.service`。不执行 sudo、不安装或重启服务，不读取 TOML 内容；只检查服务器 `/opt/campus-ai/shared/config.local.toml` 是否为普通文件、归 root/当前账号所有、仅所有者可访问且当前账号可读。配置语义及生产认证仍未验证。

计划页面显示阻止项与空间要求，摘要同时绑定实际检查快照。检查不完整、超时或输出格式异常时拒绝生成计划；Python 不存在时显示探针不可用。目录链接/错误类型、不可信所有者、组或其他用户可写、已有同名版本、配置不就绪、不可写安装父目录、空间不足、Python 低于 3.11、缺 venv/ensurepip、未知端口或服务状态等均列为阻止项。空间要求至少 1 GiB 且不低于产物展开大小三倍，仅为当前保守门槛，不替代依赖和备份的实际容量预算。

首次安装不接管已有 current、同名应用服务或已占用的 8000 端口；允许审阅手工准备的安全目录，但执行前仍需核对未识别文件。更新要求 current 指向 releases 下的安全版本目录，且 API/Worker 已加载并运行；8000 端口监听只提示需核对进程归属，不据此证明属于本应用。80/443 占用列为需人工核对的阻止项，不自动覆盖现有站点。已有 dist 未经完整构建及缺少 python3/nginx 同样阻止执行。

当前这些结论来自有限的只读快照，**未验证 sudo、服务文件/站点内容、端口进程归属、真实 venv 创建、依赖安装、数据库及 OIDC、备份和健康检查**。即使没有已知阻止项，`execution_available` 仍为 false，不出现可执行的安装按钮。探针使用假文件系统和假 SSH 传输测试，尚未连接真实服务器验证。

## 本地发布包

在项目根目录执行（不读取本地 TOML 或环境密码，不连接服务器）：

```bash
./.venv/Scripts/python.exe scripts/package_release.py --release release-20261019
```

默认先执行 `pnpm build`，失败就停止，不生成新包。成功后按白名单打包后端 Python、增量迁移、依赖文件、Alembic 配置与前端 dist。项目根目录的 `config.local.toml`、`.env`、数据库、测试、node_modules、缓存和源码映射不进入发布包；这不是源码中的硬编码密钥扫描，发布前仍须审查源代码和前端内容。

归档包含逐文件 SHA256/长度清单和构建状态，按内容摘要保存为 `.tmp/deployment-artifacts/<SHA256>.tar.gz`。相同内容和版本产生相同包，不覆盖已有文件。校验不解包，拒绝非法路径、链接、重复文件、未列入白名单的文件及与清单不符的内容；限制压缩大小 64 MiB、单文件 32 MiB、文件内容合计 128 MiB、最多 4096 个业务文件，同时限制整个解压流。生成计划时再次读取并校验实际字节，不能只填写任意摘要。

可独立复验已生成的包：

```bash
./.venv/Scripts/python.exe scripts/package_release.py --verify-only --release <SHA256>
```

若本机完整构建受 `spawn EPERM` 阻塞，可显式使用 `--use-existing-web-dist` 生成**仅供审阅**的包。清单及页面会标记 `prebuilt-unverified`，不保证现有 dist 对应当前源码。不得把此包视为已通过生产构建；执行前必须重新完整构建。所有包当前均返回 `deployment_ready=false`，未锁定依赖解析、验证 Linux 安装和真实运行，也尚无上传或执行能力。
